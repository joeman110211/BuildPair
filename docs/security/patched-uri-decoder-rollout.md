# Patched URI decoder trial (Expo SDK 57)

This branch replaces the known vulnerable `decode-uri-component@0.2.2` transitive package under `expo-router -> query-string@7` with **the upstream fixed `0.5.0`** via an npm alias and a minimal CommonJS bridge.

`query-string@7` synchronously calls `require('decode-uri-component')`; the patched upstream version exports ESM. The bridge preserves the CommonJS callable interface while forwarding all decoding to the original patched code. It does not fork or reimplement the vulnerable algorithm.

- Scoped root npm override: `decode-uri-component -> $decode-uri-component`.
- Root dev dependency points to `packages/decode-uri-component-bridge`, and that package pulls `patched-uri-decoder: npm:decode-uri-component@0.5.0`.
- Lockfile must be regenerated by npm 11.19.0. Do not manually edit integrity hashes.
- Branch-only GitHub workflow regenerates the lockfile, runs lint, typecheck, unit tests, web export and checks the actual audit report. Only after that does it commit the lockfile.
- Before merging: inspect the workflow, require web browser hydration, sign-up / deep-link navigation, native Android/iOS navigation, and validate production request routing. An npm audit count decreasing is not proof of application compatibility.
- Do not touch BuildPay, paid subscriptions, complimentary Pro grants, database migrations, or unrelated features.
- `braces` and `node-forge` high-severity advisories remain unpatched upstream. This trial is not claimed to resolve them.
